# 可展示案例：减少平移误报，同时保留剩余失败

这份案例展示的是一个视频复核工程项目：把输入文件、时间戳、检测规则、候选回放和复核结论连接起来，并用固定夹具说明一次算法改动带来的实际变化。**原规则 8 TP / 26 FP / 2 FN，运动补偿 8 TP / 4 FP / 2 FN；两段平移视频的 22 个切镜误报降为 0，切镜附近 2 个闪光漏匹配仍保留。**

这些数据来自[公开事件指标](../examples/demo_v2/test/metrics.json)，对应程序渲染的受控 MP4 和构造参考标签。没有生成视频模型调用，没有真人质量评分；不能将分数解释为某个视频模型的生成质量，也不能据此承诺真实视频的检出率。

## 问题、实现与比较条件

相邻两帧变化大，可能是切镜，也可能只是相机平移。原规则直接用结构差判切镜，容易把平移形成的新画面当作多次切镜。v2 先追踪特征点，用 LK 光流和 RANSAC 估计全局平移、旋转与缩放，再在有效重叠区域计算补偿后的结构残差。

运动估计必须满足有效跟踪数、内点率、尺度和重叠范围要求；失败时残差为 `null`，`motion_status` 说明原因，切镜检测回退原始结构差。冻结仍用原始帧差与源 PTS 持续时间，否则把平移补偿到接近静止后，反而可能误报冻结。

本次配对消融保持如下条件相同：同一测试视频、同一 36 组校准网格选出的阈值、同一切镜保护、同一事件匹配协议，仅打开/关闭运动补偿。不是分别给两套算法调到最好后再排名。

[数据集清单](../examples/demo_v2/fixtures/dataset.json)包含 28 段事件素材：校准 8 段来自 2 个来源组，测试 20 段来自 4 个声明来源组。正常运动、冻结、闪烁和切镜之外，还包含平移、变焦、低纹理运动、有意静止、淡入淡出、切镜邻近闪光。一个来源的不同变体相互相关，28 段不等于 28 个独立真实来源。非零起点、VFR、单帧等额外时间检查不计入这 20 段事件测试的分数。

测试夹具在开发中已被查看，因此这是固定回归集合上的描述性结果。来源组隔离与冻结配置有助于避免直接复用校准内容，但不能将这次开发已查看的集合包装为盲测或外部泛化研究。

## 结果与分母

| 事件 | 原规则 TP / FP / FN | 补偿后 TP / FP / FN | 参考事件 |
|---|---:|---:|---:|
| 静止候选 | 2 / 2 / 0 | 2 / 2 / 0 | 2 |
| 亮度突变 | 2 / 2 / 2 | 2 / 2 / 2 | 4 |
| 切镜候选 | 4 / 22 / 0 | 4 / 0 / 0 | 4 |
| 合计 | **8 / 26 / 2** | **8 / 4 / 2** | **10** |

TP 是与同片同类型参考事件成功匹配的候选数；FP 是未匹配候选数；FN 是未匹配参考事件数。区间按源 PTS 秒数表示，使用半开区间 `[start, end)`。tIoU 是时间交集长度除以并集长度；门槛固定为 `0.3`，达到门槛即可匹配。程序先最大化一对一匹配数量，再最大化总 tIoU，不用可能漏配的简单贪心。

原规则预测 34 个事件，补偿后预测 12 个事件，参考始终为 10 个。因此 precision 为 `8/34 = 0.2353` → `8/12 = 0.6667`，recall 为 `8/10 = 0.8` → `0.8`，F1 为 `0.3636` → `0.7273`。这是误报减少，召回没有提高。零分母报告 `null` 并说明原因，不改成 0 或 100%。旧 [reference_run](../examples/reference_run/verification.json) 是历史 v1 产物，匹配协议不同，不能与 v2 分数混加。

两段 `pan` 各从 11 个切镜误报降为 0。12 段构造真值为空的正常/反例片中，有报警的片数从 `4/12` 变成 `2/12`，保留的两段是有意静止。它们虽然没有标注故障，却满足原始静止规则，需要由复核判断意图。

运动估计失败 `103/940` 帧对，约 10.96%，其中低纹理是重要困难。失败帧对仍被分析，不能删去失败样本后只展示可靠拟合。20 个计划测试片本次均成功处理，`n_planned=n_attempted=n_valid=n_scored=20`；如果另一次执行失败，应同时展示计划与成功分母，不能把失败片算成零报警正常片。只有 4 个声明测试来源组，本例没有发布推断性置信区间。

## 三段适合现场展示的过程

先按[入门指南](GETTING_STARTED.zh-CN.md)安装并启动项目根的 `serve`。以下网页在本机服务中运行；在 GitHub 直接点 HTML 可能只显示源码。

### A. 平移误报消除：说明改动解决了什么

打开[平移时间线](http://127.0.0.1:8765/examples/demo_v2/test/test_challenge_1_pan/timeline.html)，连续看完整段运动，再对照[指标原始 JSON](../examples/demo_v2/test/metrics.json)中的：

- `ablation.original_rule.by_kind.pan`：2 段片，22 FP；每段 11 FP。
- `ablation.motion_compensated_rule.by_kind.pan`：同样 2 段片，0 FP。
- `per_clip`：同片时长、两种规则结果及运动拟合状态。

保存的单片时间线展示开启补偿后的候选；原规则计数来自同次评测中的配对计算。不要称页面同时展示了两份原/新报告。若想现场生成独立对照，只对这一片使用相同冻结配置和两个新目录：

```bash
.venv/bin/python -m video_temporal_audit analyze \
  --video examples/demo_v2/fixtures/media/test_challenge_1_pan.mp4 \
  --config examples/demo_v2/calibration/config.json \
  --motion-compensation off --output runs/pan_off_01
.venv/bin/python -m video_temporal_audit analyze \
  --video examples/demo_v2/fixtures/media/test_challenge_1_pan.mp4 \
  --config examples/demo_v2/calibration/config.json \
  --motion-compensation on --output runs/pan_on_01
```

这是读者可选的后续重现命令；本次文档轻量验收没有再次运行这两条平移对照。

### B. 有意静止：说明候选如何转为复核意见

打开[有意静止时间线](http://127.0.0.1:8765/examples/demo_v2/test/test_challenge_1_intentional_static/timeline.html)。该片出现 1 个静止候选，覆盖约 0–4 秒；构造故障参考却为空。连续回放并查明素材设计后，可选择“合法变化”，写“画面本来就有意保持静止”的具体依据，再导出 JSONL、用 CLI 导入到独立目录。

可展示的产物是原候选仍在，`human_reviews` 单独记录意见，`result.json` 的 `reviewed` 计数增加。只点“保存草稿”不算交付成功。复核行绑定 `clip_id / media_sha / config_digest / report_digest`，不能把另一片同名 E001 的结论直接复制过来。

### C. 切镜附近闪光：说明失败没有被隐藏

打开[切镜邻近闪光时间线](http://127.0.0.1:8765/examples/demo_v2/test/test_challenge_1_cut_near_flash/timeline.html)，同时看[该片报告](../examples/demo_v2/test/test_challenge_1_cut_near_flash/report.json)及数据集的参考区间。

这类素材两片合计在原规则和补偿规则下均为 **2 TP / 2 FP / 2 FN**。每片成功匹配切镜，但附近的真实闪光未匹配；另外仍各有 1 个未匹配亮度候选。不能因页面出现过亮度报警就把 FN 改成已检出：时间区间与参考的 tIoU 需要达到门槛。切镜保护的副作用仍在，本次全局运动补偿没有修好它。

剩余总计 4 FP 来自两段有意静止的 2 个候选，加这两段的 2 个未匹配亮度候选；2 FN 则是邻近切镜的闪光参考事件。展示时保留这两个失败片，不只播放平移成功片。

## 时间定位也是可展示成果

[offset_flash 报告](../examples/demo_v2/timing/offset_flash/report.json)提供一个容易手算的例子：源首帧 `5.0`，事件源 PTS `7.0–7.25`，对应相对播放 `2.0–2.25`，点击回放从 `1.5` 秒开始。展示时应同时看页面定位成功状态与播放器实际推进，不能只看按钮是否可点击。

这个文件还揭示一个容易夸大的边界：源 MP4 独立 FFprobe 的流时长为 **3.916667 秒**，不是 4 秒。源末帧显示时长缺失，分析使用中位帧间隔估计尾帧，得到源坐标结束 `9.0`、相对结束 `4.0`。预览明确编码约 0.083333 秒的尾帧显示，读回结束 `4.0000003`，与分析末尾误差约 `0.0000003` 秒。

`source_end_is_estimated=true`、`source_last_duration_source=median_delta_ESTIMATE` 和 `timing_warnings` 必须随说明一起保留。预览末包时长是实测为正，不能反过来证明原片尾时长也被实测。映射检查容差 `0.00003` 秒用于逐帧与末尾覆盖验证，不能当成检测算法的故障时间精度。

## 复核绑定与非法输入的实际加固

当前导入先检查全部数据，再复制到新目录：八个字段必须是字符串，事件必须存在且不重复，依据不能为空；源报告的有效配置和事件摘要会回算，预览哈希也会核对。已有复核同样校验，避免未知事件制造负待复核数。正确新复核可替换同一事件的旧意见，候选事件不被重写。

非法 tIoU（零、负数、布尔、NaN、无穷或超过 1）在匹配函数被拒绝，合法范围为 `(0,1]`；不是给 CLI 增加了一个 `--tiou` 开关。`config=null`、非字符串复核字段、错误摘要、缺失/损坏/只有音轨的媒体、非空或文件型输出路径，都有明确错误出口。已处理 CLI 输入错误退出 **2**；不能把退出 2 的旧输出目录当成成功。

[verification_v2.json](../verification_v2.json)保留角色20时点的 59 项 Python 测试、12 项 JavaScript 协议断言、24 份公开报告的摘要校验、24 个预览的独立尾帧检查，以及尾帧修复后的实际浏览器 Range/Blob 回放。保存的完整 demo 在 macOS arm64 / Python 3.12.14 上运行约 **15.75 秒**；后续非法输入修复未重新跑完整 demo，指标字节保持不变。

本次说明文档只轻量复跑一个已有闪烁片：48 帧、1 候选；合法协议复核导入后 1 已复核、0 待复核，原文件和事件保持；4 类错误退出 2；Range 返回 206 和请求的 32 字节；服务中断后退出 0、端口关闭。复核测试行明确为 `uncertain` 协议数据，不是真人评分。没有在这次文档任务里重跑全套测试、完整 demo、全新依赖安装或浏览器。
